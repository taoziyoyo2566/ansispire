## Intent per change

### Guard 8 rewrite — root cause + fix

The previous round's WU-2 shipped `scripts/archive_branch.sh` with a
two-path merge check: (a) ancestor relationship for true-merge, (b)
`git cherry`-based patch-id walk as fallback for squash-merge.

Path (b) was based on a misreading of `git cherry`'s semantics.
`git cherry <upstream> <head>` walks each commit on `<head>` and looks
for a matching **per-commit** patch-id on `<upstream>`. With squash-
merge:

- The source branch has N commits with patch-ids `p1..pN`.
- Squash produces 1 commit on target with a **combined** patch-id
  `P_combined ≠ any pi`.
- `cherry` reports all N as `+` (missing).

Diagnostic on PR #17 (the very first dogfood call):

```
$ git cherry origin/dev origin/feat/dev-tooling-review-optim
+ cbd9d91 + 6cb9e5b + de3b05b + a9f0d11 + a0566a7 + fc38c21
```

Script then exits at `missing=6 ≠ 0` → refuse to archive a branch that
is in fact merged. There is no `git cherry` form that makes this work
for squash — the comparison the script author wanted (`every patch on
BRANCH is reachable from TARGET`) is not what cherry computes.

The fix replaces path (b) with a `gh pr view "$PR_NUM" --json state -q
.state` lookup. The script already collects `PR_NUMBER` as the third
positional arg (for the tag annotation message), so this introduces no
new arguments. The path is conditional on `gh` being installed and
emits a clear error if not.

Three-path acceptance now:

1. Ancestor (`git merge-base --is-ancestor TIP origin/TARGET`) →
   accept (true-merge, fast-path, no `gh` round-trip).
2. PR state via `gh pr view PR_NUM --json state` returns `MERGED` →
   accept (squash-merge case).
3. Else refuse with an error that names both checks and reports the
   actual PR state seen (or `unknown` if `gh` couldn't look it up).

The header comment block (`# 6.`) is updated to describe both paths
instead of only ancestry.

### WU-2 — watch-pr-checks.sh: empty-rollup + non-FAILURE-conclusion bugs

Discovered during iter-2 push to PR #18: `./scripts/watch-pr-checks.sh
18` returned exit 0 "all green" within ~10 seconds, while CI actually
had 7 of 13 checks pending (4 molecule scenarios, dry-run, 2 API
contract). Three real bugs in one python block:

1. **`total == 0` declared green** (HIGH; observed). Right after
   `git push`, GitHub takes 10–30s to register workflow runs. Polling
   in that window returns `statusCheckRollup: []`. The old code
   computed `pending = sum(1 for c in checks if not c.get(...))` over
   the empty list → `pending = 0` → `if pending == 0: exit 0`. Fix:
   explicit `if total == 0: print "(not yet registered)"; exit 99`
   before computing done/pending.

2. **Non-FAILURE conclusions silently passed** (MEDIUM; latent).
   GitHub Actions conclusion enum is wider than `{SUCCESS, FAILURE}`:
   `CANCELLED`, `TIMED_OUT`, `ACTION_REQUIRED`, `STALE`,
   `STARTUP_FAILURE`, `SKIPPED`, `NEUTRAL`. The old `failures = [...
   if conclusion == 'FAILURE']` only flagged FAILURE; the other
   non-OK terminal states were counted as `done` with `failures = []`
   → exit 0. Fix: invert to allow-list `OK_CONCLUSIONS = {'SUCCESS',
   'SKIPPED', 'NEUTRAL'}`; everything else with a conclusion set =
   failure-equivalent.

3. **Wave-registration race** (LOW; theoretical, NOT fixed this
   round). If GitHub registered workflow runs in waves (only fast
   ones first, then slow ones), polling between waves could see e.g.
   6/6 done = "all green" before the slow 7 even appeared.
   Mitigation: in practice GitHub triggers all `on: push` workflows
   from a single event and they're all registered within ~1s of each
   other; the observed race is bug #1's empty-rollup window, not a
   true wave. Documented in `watch-pr-checks.sh` header for future
   reference; fix deferred unless observed.

Bugs 1 and 2 were both caught by an **adversarial gate-1 review** of
the patch (the same technique that caught the archive_branch.sh HIGH
regression in iteration 1 of WU-1). The check: enumerate "what
attack scenarios does this NOT block" before declaring direction
clean. Without that lens bug 2 would have shipped.
