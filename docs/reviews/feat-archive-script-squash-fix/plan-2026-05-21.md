## 3. Current-state assessment (root cause)

Script line 122:
```bash
missing=$(git cherry "origin/$TARGET" "$TIP" "$base" | grep -c '^+' || true)
```

`git cherry <upstream> <head> [<limit>]` walks each commit on `<head>` since `<limit>` (or merge-base), computes its patch-id, and looks for a matching patch-id on any commit reachable from `<upstream>`. For a squash merge:
- The branch has N commits, each with its own patch-id `p1..pN`.
- Squash produces 1 commit on target with combined patch-id `P_combined` ≠ any `pi`.
- `git cherry` reports all N commits as `+` (missing).

Diagnostic on PR #17:
```
$ git cherry origin/dev origin/feat/dev-tooling-review-optim
+ cbd9d91 + 6cb9e5b + de3b05b + a9f0d11 + a0566a7 + fc38c21
```

All 6 are `+`. Script exits with `missing=6 ≠ 0` → refuse.

The original script's comment (`# (b) every patch-id reachable from BRANCH is also reachable from TARGET (squash-merge case)`) misstates `git cherry`'s semantics: cherry checks per-commit, not aggregated. There is no `git cherry`-based way to detect squash-merge.

## 4. Decision rationale per change

**Change**: replace cherry block with `gh pr view --json state`.

**Why this over alternatives**:
- *vs. reconstructing combined patch-id*: would require `git diff origin/$TARGET...origin/$BRANCH | git patch-id` plus walking target's recent commits looking for a matching combined patch. Multi-step, fragile (which window of target commits to compare?), and offers no real safety benefit over asking GitHub directly.
- *vs. `--force-squash` flag*: shifts the safety burden to the operator (CLAUDE.md §4 archive recipe is precisely the place where we don't want to rely on operator vigilance — it's the high-blast `git push :branch` step).
- *vs. trusting only PR_NUM input*: still requires fetching `origin` first and confirming both refs exist (guard 6+7). PR state is a sanity check, not a replacement for the ref existence checks.

**Why keep ancestor fast-path**: branches that merge as true merge commits (not squash) still have `tip is ancestor of target` true. Skipping the `gh` shell-out for those is faster and avoids a hard dependency on `gh` for the non-squash path (the script header doesn't currently list `gh` as a prereq; the new gate makes it conditionally required for squash-merge archival).
