## Intent per change

### WU-1 — Makefile audit URL from .env
The Makefile's `controller-audit-up` echo previously hardcoded `:3310`; in
the recent fix branch this had to be manually corrected to match
`docker-compose.yml`. Reading from `.env` (which `manifest-sync` writes)
closes the drift class entirely — no more "two files have to agree" debt.

### WU-2 — `scripts/archive_branch.sh`
CLAUDE.md §4's archive recipe is the most consequential workflow doc
(it ends with `git push origin :<branch>` — the high-blast step). The
recipe was written as two parallel code blocks for `feat/` and `fix/`
branches; Codex caught that an agent could copy across types and
delete the wrong branch. This script accepts the branch type as a
positional argument, computes the slug + tag from it, and gates every
destructive step on a verification (tag pushed first, then branch
deleted; squash-merge detection via `git cherry` since true-ancestry
fails for squash merges).

### WU-3 — `scripts/check_claude_md_links.sh`
CLAUDE.md is repo governance loaded into every session as resident
context. Wikilinks (`[[name]]`) belong to the agent's
`~/.claude/projects/*/memory/` namespace — they're dead references
from the repo's point of view. Codex caught one in the previous round
(`[[feedback-branching-model]]`). The linter is short (~30 lines of
actual logic) and chained into `make verify`, so the same mistake
fails the same gate that lint / detect-secrets / pytest do.

### WU-4 — `make review-local`
The `git merge-base @{u} HEAD` + diff-stat + diff-check sequence was a
standing pre-push ritual that lived in muscle memory. Codifying it
gives a single command for "what am I about to push" and a fallback
(`origin/dev`) for the very first run on a fresh branch (the case
where no upstream is set yet — common after the §4-mandated
`git checkout -b feat/<topic>`).

### WU-5 — Land stashed workflow scripts
`scripts/push-and-watch-pr.sh` + `scripts/watch-pr-checks.sh` encode
the "push to PR branch + background-watch CI" workflow that this
session has been using by hand for the past two PRs. They were
previously in `git stash@{0}` since the TASK-007 round. Bundling them
with the other dev-tooling work avoids leaving an indefinite-life
stash and gives them their natural home.
