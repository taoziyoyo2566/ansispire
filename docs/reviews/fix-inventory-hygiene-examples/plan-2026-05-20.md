## §1 Purpose / Scope

Move example variable files out of the live `inventory/<env>/group_vars/` and `host_vars/` paths so Ansible no longer auto-loads them. Today's "protection" is only alphabetical sort order (real `vault.yml` happens to load after `vault.example.yml`); this is fragile.

### In scope
- `inventory/dev/group_vars/all/vault.example.yml` → `inventory/examples/group_vars/all/vault.example.yml`
- `inventory/dev/group_vars/all/secrets_external.example.yml` → `inventory/examples/group_vars/all/secrets_external.example.yml`
- `inventory/dev/host_vars/web01.example.com/` (dir) → `inventory/examples/host_vars/web01.example.com/`
- `inventory/dev/group_vars/all/vault.yml` reference updates (lines 4 and 11)
- Self-reference updates inside the moved example files
- New: `inventory/examples/README.md`
- New: this plan + round1 changelog

### Out of scope
- F2 (default inventory = prod footgun) — separate decision needed
- F3 (hub layered-mode docs) — doc-only nit
- TASK-007.B / .C (TODO tracked separately)
- Dev-tooling scripts in `stash@{0}` (separate `chore/dev-tooling-pr-checks` PR)
- `inventory/local/vault.yml.example` — suffix `.yml.example` is NOT in Ansible's auto-load extension set, leave in place

## §4 Risks

- Hidden literal references: a playbook/Jinja/python file may hard-code `vault.example.yml` path. Pre-PR grep covers `*.yml *.yaml *.j2 *.py`.
- Mirror-layout confusion: someone may try `-i inventory/examples` directly. Mitigation: README disclaimer; tree contains no `hosts.ini` so `ansible-inventory -i inventory/examples` fails fast.
