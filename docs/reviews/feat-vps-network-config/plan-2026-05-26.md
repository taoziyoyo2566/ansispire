## 3. Design Decisions（逐项 rationale）

- **D1 additive overlay，不接管 v4、不禁 cloud-init**（user①）：新文件 `/etc/netplan/90-ansispire-ipv6.yaml`（序号 90 > cloud-init 50，模式 0600）只写 IPv6 地址 + IPv6 默认路由 + 可选 IPv6 DNS。**不写 IPv4 默认路由** → 规避「Conflicting default route」报错。安全红利：SSH 走 v4，overlay 不碰 v4 → IPv6 配错断不了 SSH。
- **D2 dead-man's-switch 安全 apply**（user②）：见 §5.2。即便 D1 已大幅降低锁定风险，role 是**可复用能力**，须 safe-by-construction（未来若用于 v4 变更或控制通道走被改地址时仍安全）→ 回滚守卫常驻 role。
- **D3 OS-family 分派**（user③）：`tasks/main.yml` 按 `ansible_facts.os_family` 分派 → `tasks/debian.yml`（netplan，本轮实现）/ `tasks/redhat.yml`（nmcli，本轮 stub + `assert` 报「未实现」+ TODO）。镜像 `infra_baseline` 的 `redhat.yml` 拆分。
- **D4 模板 + handler 幂等**（修正 ChatGPT 的命令式 `mv`/无条件 apply）：`template` 渲染 overlay；apply 块 `when: overlay_render is changed`。删除所有 `ignore_errors: true`，备份用 `creates`/`stat` 守卫 + 正确 `failed_when`（[[contract-gate-strictness]]）。
- **D5 host_vars 键名 `network`**（与既有 `network_tuning` 区分）：`network` = L3 地址/路由/DNS 声明；`network_tuning` = sysctl。两键并存，feature-map 写明边界。
- **D6 IPv6 归一化用于幂等比对**：`2001:02C0:...0001` 内核归一为 `2001:2c0:...:1`。验证/幂等比对前先归一（`ipaddr` filter 或 `python3 -c`），否则恒报 changed。模板写入沿用 user 给的形态即可（netplan 接受）。
- **D7 调用入口独立 playbook**（不并入 onboard）：网络配置敏感，须显式 opt-in，不在 onboard 自动跑。

## 4. host_vars `network` 契约（草案）

```yaml
# inventory/vps_runner/dev/host_vars/<alias>.yml 追加
network:
  managed_by_ansible: true        # 总开关，缺省 false → role 跳过
  interface: ens10                # 必填
  ipv6:
    enabled: true
    address: "2001:02C0:0100:0417:0018:cafe:0609:0001"
    prefix: 64
    gateway: "2001:02C0:0100:0417::1"
    nameservers:                  # 可选；缺省则不写 v6 DNS（保留 cloud-init 的）
      - "2001:2C0:1:C::16"
      - "2001:2C0:11::C95"
  # ipv4: 本轮不渲染（cloud-init 自管）。schema 预留键以便未来 full-takeover，role 默认忽略。
  apply:
    revert_timeout: 120           # dead-man's-switch 秒数，缺省 120
```

`roles/network/meta/argument_specs.yml` 对上述做类型/必填校验（interface 必填、ipv6.address 在 enabled 时必填、prefix 1-128、gateway 与 address 同段校验留 best-effort）。

## 5. Role 结构 + 安全 apply 序列

### 5.1 文件布局
```
roles/network/
  defaults/main.yml          # network: {managed_by_ansible: false} 等安全缺省
  meta/argument_specs.yml    # 契约校验
  tasks/main.yml             # os_family 分派 + managed_by_ansible 守卫
  tasks/debian.yml           # netplan overlay 渲染 + 安全 apply（本轮实现）
  tasks/redhat.yml           # stub: assert 未实现 + TODO（留接缝）
  templates/ipv6-overlay.yaml.j2
  handlers/main.yml          # （apply 内联编排，handler 仅留必要项）
playbooks/configure_network.yml   # hosts: vps_targets, become, 仅 include_role network
```

### 5.2 Debian 安全 apply 序列（tasks/debian.yml，镜像 onboard 防锁定纪律）
1. `stat` 检查 overlay 是否已存在 → 备份现有 `/etc/netplan/` 到 `/root/netplan-backup/<ts>/`（`creates` 守卫，不用 ignore_errors）。
2. `template` 渲染 `90-ansispire-ipv6.yaml`（mode 0600），register `overlay_render`。
3. **以下全部 `when: overlay_render is changed and not ansible_check_mode`**：
   a. `command: netplan generate`（校验，失败 loud → 任务红，不 apply）。
   b. **布回滚守卫**：`systemd-run --on-active={{ revert_timeout }} --unit=ansispire-netplan-revert --collect <revert.sh>`，revert.sh = 删除 overlay + 还原备份 + `netplan apply`。
   c. `command: netplan apply`。
   d. 控制端验证可达：`wait_for host={{ ansible_host }} port={{ ansible_port }}` delegate_to localhost + `wait_for_connection`（镜像 onboard）。
   e. **成功 → 取消守卫**：`systemctl stop ansispire-netplan-revert.timer`（+清理）。失败 → 守卫到点自动还原，任务报错。
4. 幂等：第二次运行 `overlay_render` 未变 → 整个 apply 块 skip，`changed=0`。

> 说明：本轮 SSH 走 v4、overlay 不碰 v4，3d 的可达验证恒通过、守卫实际不触发——这是**有意的纵深防御**（role 通用性要求），plan 不夸大其在本场景的作用。

## 7. Risks & Mitigations
- **R1 Debian 13 netplan 合并语义与 24.04 不同** → T5 在 debian:13 容器复测；若不一致，回退「full-takeover 自动发现 v4」方案（plan 增补）。
- **R2 systemd-run 不可用（非 systemd 主机）** → 守卫降级为 `at` job；jpntt 两台均 systemd，本轮不阻塞。
- **R3 真机下发风险**（后续 round）→ 串行 `serial: 1`、先 `--check`、保留控制台兜底、user 显式授权。
- **R4 命名 `network` 与 ansible 内部无冲突**，但与 `network_tuning` 语义近 → feature-map 显式划界。
