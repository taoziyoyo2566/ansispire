## §1 Purpose / Scope / Out-of-scope / Judgment Criteria

### 1.2 Scope

**A. Core helpers** in `plugins/vps_runner/vps_runner.py` (constants `SSH_CONFIG_TEMPLATE` / `DEFAULT_SSH_CONFIG_DIR` / `DEFAULT_SSH_MAIN_CONFIG` / `DEFAULT_PERSONAL_IDENTITY_FILE` already scaffolded at commit `0eb7ec8`):

1. `prompt_new_host(env: str, *, defaults: dict | None = None) -> dict` — interactive wizard. **4 prompts** (per user 2026-05-22 decision Q1=b):
    ```text
    Alias [必填]:              <user-typed>
    IP / hostname [必填]:      <user-typed>
    Managed SSH port [1156]:    ↩ (default 1156)
    Managed SSH user [ansible]: ↩ (default ansible)
    ```
    Bootstrap user/port/auth are NOT prompted (group_vars `vps_runner_defaults.bootstrap_user=root` + `bootstrap_port=22` cover the typical case; non-typical → use flag mode or hand-write).
    - Validates: alias non-empty + no duplicate (`add_host` will recheck); IP non-empty; port ∈ [1024, 65535] and ≠ 22; user non-empty.
    - On invalid input: print the constraint, re-prompt the same field (validation loop).
    - On `EOFError` (no stdin) / `KeyboardInterrupt`: print abort message, return None (caller exits gracefully).
    - On `sys.stdin.isatty()` false: refuse with "wizard requires a TTY; use flag mode: `make vps-add-host ALIAS=… IP=…`".

2. `write_ssh_config(alias: str, *, hostname: str, port: int, user: str, identity_file: Path = DEFAULT_PERSONAL_IDENTITY_FILE, ssh_config_dir: Path = DEFAULT_SSH_CONFIG_DIR) -> Path` — render `SSH_CONFIG_TEMPLATE` (`ssh_config_entry.j2`) via inline Jinja2 → `<ssh_config_dir>/<alias>.conf`.
    - Renders with a single `server` dict: `{alias, host=hostname, managed_port=port, managed_user=user, identity_file=str(identity_file)}` (matches existing template's `{{ server.alias }}` etc.)
    - Idempotent overwrite (write each call; file content is determined by inputs).
    - If `ssh_config_dir` does not exist: `mkdir(parents=True, mode=0o700)`.
    - File chmod 0o600 after write.
    - Returns the written file path.

3. `delete_ssh_config(alias: str, ssh_config_dir: Path = DEFAULT_SSH_CONFIG_DIR) -> bool` — delete `<ssh_config_dir>/<alias>.conf`.
    - Idempotent: returns True if file existed and was removed; False if file did not exist; never raises.

4. `check_include_directive(ssh_config_path: Path = DEFAULT_SSH_MAIN_CONFIG) -> bool` — read `~/.ssh/config`; return True iff a non-commented line matches `r"^\s*Include\s+(.+/config\.d/.+|config\.d/.+)$"` (handles relative + absolute forms).
    - Missing file → False; never raises.

**B. CLI changes** in `plugins/vps_runner/cli.py`:

1. `_cmd_add_host` — branch on `args.alias` presence (argparse: change `alias` from positional to optional):
    - `alias` absent → call `prompt_new_host()`; on None (abort), return rc=130; else `core.add_host(...)` with collected fields; then prompt `继续 onboard 吗? [Y/n]:` — on Y (default), call `_cmd_onboard` flow inline; on N, print next-step hint (matching R6 behavior).
    - `alias` present → flag mode (R6 unchanged). `--ip` becomes required only when in flag mode.
    - On TTY check failure in absent-alias path: refuse with flag-mode hint, return rc=2.

2. `_cmd_onboard` — after `core.run_playbook(...)` returns `summary.status == "successful"`:
    - Read the alias's `host_vars/<alias>.yml` to get `ansible_host` + the merged `vps_runner.managed_port` + `vps_runner.managed_user`.
    - Call `core.write_ssh_config(alias, hostname=<ansible_host>, port=<managed_port>, user=<managed_user>)` — defaults to `~/.ssh/id_ed25519` (operator key).
    - Call `core.check_include_directive()`; if False, print a warning with the exact line operator needs to add: `Include config.d/*`.
    - Failure to write SSH config is **non-fatal** (warn but do not flip the run to failure — host is already onboarded successfully; SSH config is convenience).

3. `_cmd_remove` — regardless of `--cleanup-remote`, after `core.delete_host_vars(...)` succeeds, call `core.delete_ssh_config(alias)`. Local SSH alias is meaningless without inventory; clean both together.

**C. Makefile** (`vps-add-host` target only):
- Drop the "ALIAS and IP required" hard error from R6.
- If `ALIAS=` provided AND `IP=` provided → invoke CLI with `add-host $(ALIAS) --ip $(IP) [--port $(MANAGED_PORT)] [--user $(MANAGED_USER)] --env $(ENV)`.
- If neither → invoke `add-host --env $(ENV)` and let CLI enter wizard.
- If only one of `ALIAS=`/`IP=` provided → keep the explicit error (partial flag mode is ambiguous).

## §2 Decision rationale (deltas vs plan-2026-05-17c.md)

### 2.1 Wizard scope reduction: 8 fields → 4 fields

plan-2026-05-17c.md §2.5 listed 8 wizard prompts (alias / IP / managed_port / managed_user / bootstrap_user / bootstrap_port / bootstrap_auth / sudo_needs_password). User 2026-05-22 Q1=b: collapse to 4 essential fields. Rationale:
- bootstrap_user / bootstrap_port: `group_vars/vps_targets.yml::vps_runner_defaults` already defaults to root/22 which matches typical VPS-provider out-of-box state.
- bootstrap_auth / sudo_needs_password: these are runtime concerns for `onboard --first-time --ask-pass --ask-become-pass` — not host_vars fields.
- Fewer prompts = less abort surface, faster wizard completion, less validation code.
- Non-typical bootstrap state → flag mode or hand-edit are escape hatches (both supported).

### 2.2 Key separation: explicit constants, no group_vars lookup

plan-2026-05-17c.md §2.4 proposed reading `vps_runner_defaults.ssh_config.identity_file` from group_vars. Two problems with that:
- The actual group_vars key is `vps_runner_defaults.identity_file` (no `ssh_config` nesting) and its value is `~/.ssh/ansispire_ed25519` (automation key) — opposite of plan's stated design.
- Pulling identity_file out of group_vars requires parsing a templated value (`{{ lookup('env', 'HOME') }}/.ssh/...`) — fragile.

User 2026-05-22 confirmed two-key model: Ansible uses `ansispire_ed25519`; operator SSH config uses `id_ed25519`. R7 implements this by hard-coding `DEFAULT_PERSONAL_IDENTITY_FILE = ~/.ssh/id_ed25519` as a module constant (already scaffolded at `0eb7ec8`); SSH config write never reads group_vars; Ansible execution path (`run_playbook`) continues to honor group_vars' `vps_runner_defaults.identity_file` unchanged. Two paths are independent.

### 2.3 Three input modes (not two)

plan-2026-05-17c.md offered wizard + flag. User 2026-05-22 added template-manual as a first-class third mode for operators who want to bypass CLI entirely. R7 supplies the template file under `plugins/vps_runner/examples/` (slim — Q2=a). No code change needed to support hand-editing (it already works); template makes the path discoverable.

### 2.4 Per-alias SSH config file, not single `ansispire.conf`

Same rationale as plan-2026-05-17c.md §2.1 — carries over: per-alias files (`~/.ssh/config.d/<alias>.conf`) give clean add/remove semantics; single multi-host `ansispire.conf` would require parse-edit-rewrite cycles and risk losing host entries when a single host is changed.

### 2.5 Onboard post-success SSH config write (not via Ansible task)

Same rationale as plan-2026-05-17c.md §0.2 — carries over: writing the operator's local `~/.ssh/config.d/` is control-plane Python's job; an Ansible task `delegate_to: localhost` would conflate concerns.

### 2.6 Remove always cleans local SSH config

plan-2026-05-17c.md §2.3 — carries over: `--cleanup-remote on/off` controls remote sshd drop-in cleanup only. Local SSH alias is meaningless without inventory; if alias is being removed from inventory, the local SSH config file must go with it.

### 2.7 Why warn-only on missing `Include config.d/*`

User's `~/.ssh/config` is operator-edited turf. Modifying it programmatically is invasive (loses comments, risks breaking unrelated host stanzas). Print the exact one-liner needed and let user add it once.
