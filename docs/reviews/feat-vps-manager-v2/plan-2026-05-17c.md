### 0.2 W-R18 Framework Best-Practice Pre-Check
- **交互式 Python CLI**: 标准 `input()` + try/except KeyboardInterrupt 模式，Python stdlib 足够；无需引入 `click` / `prompt_toolkit` 这类大依赖。项目内 grep `input(` 当前无用例（首次引入），但模式标准。
- **`~/.ssh/config.d/<alias>.conf` per-host file**: OpenSSH 原生支持 `Include config.d/*` 模式。Industry 趋势是 per-host 文件（aws-cli, mosh, terraform-ssh-config 等都这样做），方便单独删/diff。
- **idempotent local file write**: 覆盖式写（每次 SSH config 内容应该可由 host_vars 推导出来），不维护"是否已存在"状态——文件在 = 已注册，删了就重新写。**避免 ruamel 之类 round-trip 库**，写 SSH config 是 generated content，不应保留人工注释（如果人手改了那个文件，下次 add-host/onboard 会覆盖；文件头加 "managed by vps_runner" 警告）。
- **onboard 写 SSH config 的位置**: 在 cli `_cmd_onboard` 后置（成功 summary 之后），不在 playbook 内部。理由：写本地文件是控制端 Python 的职责，不该把 Ansible task 带上 `delegate_to: localhost` 干本地 IO（破坏关注点分离）。

精确决策点（避免 reinvent）：

  - 复用既有模板文件（保持文件存在意义）→ 用 `jinja2.Environment` 渲染。已有 PyYAML 在用，Jinja2 是 PyYAML/ansible-runner 的间接依赖，PyPI 已装。

## §1 Purpose / Scope / Out-of-scope / Judgment Criteria

### 1.1 Purpose
让"接管新 VPS"成为一条命令：
```bash
make vps-add-host          # 启动 wizard，prompts: alias/IP/port/user/...
# 或:
.venv/bin/python -m plugins.vps_runner.cli add-host  # 同上
```
跑完后：
- `inventory/vps_runner/<env>/host_vars/<alias>.yml` 已生成
- `inventory/vps_runner/<env>/hosts.yml` 已加 alias
- 远端机器已配置（按 onboard.yml 38 个 task）
- `~/.ssh/config.d/<alias>.conf` 已生成，能 `ssh <alias>` 直连
- `host_vars` status: `active`

### 1.2 In-scope

1. **core.py**:
   - `prompt_new_host(env: str, *, defaults: dict | None = None) -> dict` — 交互式 wizard，返回字段字典；处理 KeyboardInterrupt

     - 给了 `alias` positional 参数（含 `--ip`）→ flag mode (非交互，CI 兼容)

## §2 Decision rationale

### 2.1 per-host 文件 vs 单一 ansispire.conf
| | per-host (`<alias>.conf`) | 单文件 (`ansispire.conf`) |
|---|---|---|
| add 操作 | 创建新文件 | append + 解析 |
| remove 操作 | 删文件 | 解析 + 重写（PyYAML 等价复杂度） |
| diff 友好 | ✅ 单 host 改动小 | ❌ 多 host 文件搅在一起 |
| 用户手改后果 | 单文件被覆盖 | 全部 host 注释丢光 |
| 性能 | OpenSSH 启动时多 N 个 Include 但 N << 100 时 negligible | 单文件读 |

选 per-host：用户意图明确（"一文件一 alias"）+ diff / 删干净 + 防止"覆写一个 host 牵连其他"。

### 2.2 onboard 单独跑也写 SSH config
否则会出现"add-host 后 SSH config 有，onboard 重跑后状态不变"vs"add-host 之前手工建 host_vars 再 onboard 时无 SSH config" 两种不对称。让 onboard 也写：reconcile 总是收敛到 "host_vars + SSH config 都对" 的状态。

### 2.3 SSH config 删除时机
remove 命令分两种 mode（`--cleanup-remote` on/off）：
- on：删远端 drop-in + 删本地 inventory + 删 SSH config
- off：只删本地 inventory + 删 SSH config

两种 mode 都删 SSH config，理由：本地 alias 是 inventory 的"用户面"——inventory 没了 alias 也没意义，留着误导。

### 2.4 IdentityFile 选择
用 `~/.ssh/id_ed25519`（人 key），不是 `~/.ssh/ansispire_ed25519`（自动化 key）。配置来源：`group_vars/vps_targets.yml::vps_runner_defaults.ssh_config.identity_file`（已是 `{{ lookup('env','HOME') }}/.ssh/id_ed25519`）。core.write_ssh_config 接受 identity_file 参数，cli 从合并后的 vr 字典里取。

### 2.5 wizard 输入字段
默认问 6 项，回车接受默认：
```
Alias [必填]:              de-d12-1
IP / hostname [必填]:      203.0.113.42
Managed SSH port [1156]:   ↩
Managed SSH user [ansible]: ↩
Bootstrap user [root]:     ↩
Bootstrap port [22]:       ↩
Bootstrap auth [pass]:     password | key  (默认 password)
Sudo needs password [Y/n]: ↩
```
确认 summary → 是否继续 onboard [Y/n]。

## §5 Risks
- **R1**: 用户手改了 `~/.ssh/config.d/<alias>.conf` 自定义内容 → onboard / add-host 重跑覆盖。Mitigation: 文件头加 `# Managed by Ansispire vps_runner — DO NOT EDIT; changes will be overwritten by next onboard/add-host`
- **R2**: 用户 `~/.ssh/config` 没 Include 行 → SSH alias 文件写了但 `ssh <alias>` 不生效。Mitigation: check_include_directive() 在写完后 warn + 给 fix 命令；不主动改用户主 config
- **R3**: wizard 在 stdin 不是 tty 时挂死（CI 没 input） → flag mode 已是 fallback；wizard 入口检测 `sys.stdin.isatty()`，false 时报错让用户用 flag mode
