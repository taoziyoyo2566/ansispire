## 2. Intent per change

### 2.1 Shim flatten (R3 §6 follow-up)
User accepted the `vps_task` shim in R3 with the agreement that it would be cleaned up in R4. The mechanical inlining went without functional change — same expressions, just moved out of the intermediate aggregator. `ansible-lint --profile production` continues to pass; all 22 tests stay green. The 3 lingering `vps_task.packages.*` references in the task body had to be rewritten too — `vps_package_install_list` was already defined in vars and just needed to be used; `vps_task.packages.remove` was inlined as `(packages | default({})).remove`.

### 2.2 Operator guide (T2.8)
Long-form, user-facing — written so an operator with **no AI in the loop** can succeed (per workspace W-R14 corollary on document-role separation). §4 walks the first-time onboard end-to-end including the manual `host_vars/<alias>.yml` creation step, exactly which fields are mandatory before kicking off `onboard --first-time --ask-pass --ask-become-pass`, and what each playbook step does. §5 codifies recovery from half-configured nodes (when SSH port has migrated but UFW/fail2ban haven't applied).

### 2.3 Per-module spec (T2.8)
Maintainer-facing; lower prose density, higher fidelity to internal shape. Architecture / execution-flow / data-flow tables exist so future agents can wire new subcommands without re-reading the source.

### 2.4 INDEX / ARCHITECTURE / README / CHANGELOG sync (T2.9 + W-R12)
Dual-track presentation is deliberate. Until Round 4-b cutover lands, both plugins coexist — and the docs reflect that with explicit "current" vs "legacy / slated for removal" markers. After cutover, vps_manager rows drop in a single edit per file.

### 2.5 Makefile (T2.9 + operator UX)
Three new targets following the existing project naming pattern (`test-X` / `test-X-integration` / `X-syntax`). `test-vps-runner` is added to `verify` so the push gate validates the new plugin every time; `test-vps-runner-integration` is **not** in `verify` (~11s real SSH timeout would slow every push). Help text is auto-derived from doc comments, so `make help` instantly lists the new targets without extra plumbing.
