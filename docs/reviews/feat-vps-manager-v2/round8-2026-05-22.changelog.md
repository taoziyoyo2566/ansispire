## 2. Intent per change

### 2.1 F1 — forward ANSIBLE_LOCAL_TEMP (P2 robustness)

`run_playbook()` calls `_scrubbed_environ(envvars)` before invoking ansible-runner — that scrub clears `os.environ` and replaces it with the whitelist, so any `ANSIBLE_LOCAL_TEMP` the Makefile exported is dropped. The plugin used to silently fall back to ansible's default `~/.ansible/tmp`, which only works when HOME is writable.

Fix is a project-local pinning: same path the Makefile uses (`$(PROJECT_PATH)/.ansible/tmp`), set at module level so it's tested and explicit; the function mkdirs it before each call (cheap, idempotent). Result: the plugin is now independent of HOME state — matches the Makefile invariance promise documented in the docstring for `_build_runner_envvars()`.

Note this does NOT also forward `ANSIBLE_REMOTE_TEMP` (the remote-side path used by managed nodes' tmpdir on the target VPS). That variable is consumed on the target, not the controller, and Ansible's default `/tmp/.ansible-${USER}/tmp` works fine on real VPS targets; the Makefile's `ANSIBLE_REMOTE_TEMP=/tmp/ansispire-ansible-tmp` is an optional override for fleets with stricter `/tmp` policies. Not pinning it from the plugin avoids implicit policy. If the fleet ever needs a project-pinned remote tmp, that becomes a separate decision.

### 2.2 F3 — trailing whitespace cleanup (P2 hygiene)

- **`docs/operations/vps-runner.md:148-149`** — original used Markdown's two-space hard-break (`  \n`) for three case statements. Replaced with a 3-item bullet list which is more idiomatic and doesn't depend on trailing whitespace.
- **`IVG-VPS-BATCH-PARALLEL.md:45`** — stray trailing space after the colon. Pure noise; stripped.
- **`plan-2026-05-22.md:231`** — trailing whitespace inside a HEREDOC blank line that represents `<Enter>` for a wizard default. The behavior is unchanged because the wizard does `input().strip()`, but visually it was just noise. Cleaned.

### 2.3 F2 — explicitly deferred

The reviewer is correct that `add_host()` lets any string through. Why we did NOT fix it here:

1. **Scope discipline.** F2's correct fix is not a one-liner: it needs a documented alias charset policy, a separate `hostname` validator (used by `write_ssh_config()`), traversal tests (`../foo`, `foo/../bar`, absolute paths, NUL bytes), SSH-config injection tests (alias with newlines), and a plan-doc paragraph on the operator-confusion path (what gets rejected and why).
2. **No exposed attack surface.** add-host inputs come from the single operator's keyboard, not a network endpoint. The risk is "operator typos a weird character and gets a confusing error somewhere downstream", not "attacker injects malicious alias".
3. **W-R20 cadence.** Mixing a security-flavor change with a robustness fix complicates the next external-review iteration. F2 deserves its own round so its reviewer hand-off is clean.

Tracked in §6 Follow-Up.
