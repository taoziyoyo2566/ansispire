## §0 Pre-execution Checklist

### 0.1 Intent / Boundaries / NFR

- **Intent**: restore the "create new managed-VPS entry" UX that legacy `plugins/vps_manager/cli.py` had via `new` / `submit` subcommands but that this branch's cutover dropped without porting.
- **Boundaries**: `plugins/vps_runner/cli.py` (add subcommand), `plugins/vps_runner/vps_runner.py` (add core helper), `Makefile` (add 6 `vps-*` wrappers including new `vps-add-host`), tests, docs. No inventory schema change.

- **Authorization**: local edits + lint + pytest + commit; no push proposed.

### 0.2 W-R18 Framework Best-Practice Pre-Check

The work generates a standard Ansible inventory file from CLI input. Ansible doesn't expose a native "add-host" primitive — closest is `ansible-galaxy init` (scaffolding) and `ansible.builtin.add_host` (an in-play module that has nothing to do with on-disk inventory). What we're doing is meta-tooling that emits standard inventory artifacts, which is a common pattern (e.g., the `cookiecutter` family, Terraform's `terraform init` scaffolding).

In-project precedent for inventory-as-file mutation:
- `core.remove_alias_from_hosts(env, alias)` — already does read-modify-write of `hosts.yml` via PyYAML
- `core.delete_host_vars(env, alias)` — already does `path.unlink()`
- `core.write_host_vars(env, alias, data)` — already used to update status after onboard
- onboard.yml `pre_tasks: assert vps_ssh.managed_port != 22 and 1024..65535` — port validation precedent

So the additions are **mirrors** of existing helpers, not new patterns. PyYAML loses comments on the hosts.yml round-trip; this loss already happens on `remove`; accepted as status quo (file is mostly mechanical; comment header recoverable via git). Not introducing `ruamel.yaml` for this round.

Conclusion: **direction matches**. Adding `add_host` + `add_alias_to_hosts` to core is consistent with the file's existing helper set; no reinvention. Source: grep of `plugins/vps_runner/vps_runner.py` (read this round) + onboard.yml `pre_tasks` assertion.

## §3 Decision rationale per change

### 3.1 `add-host` not `new`
Old name `new` was tied to "create a task draft" semantics; new model has no task drafts, just direct inventory entries. `add-host` is the verb-noun pattern that matches sibling Ansible tools (`ansible.builtin.add_host` in-play module — same name, different scope: theirs adds to runtime in-memory inventory, ours adds to on-disk inventory). The naming overlap is intentional: operators familiar with Ansible's `add_host` will guess this command's purpose correctly.

### 3.2 Field defaults
- `port=1156`: matches all 4 existing dev hosts (consistent fleet)
- `user=ansible`: matches 3 of 4 existing dev hosts (hy-hk-u24 uses `deploy`, overrideable via `--user`)
- `status=pending`: signals "not yet onboarded"; `onboard` flips to `active` on success via existing `record_run(set_status="active")` path

### 3.3 Validation
- alias uniqueness: refuse if already in `hosts.yml` `vps_targets.hosts` OR `host_vars/<alias>.yml` exists (covers both "previously cleaned hosts.yml but file remains" + "file removed but hosts.yml still references" edge cases)
- port range: must be 1024–65535 AND `!= 22` (mirror onboard.yml `pre_tasks` assertion exactly — keeps fail-fast at CLI level instead of waiting until onboard fails)
- IP: no validation beyond "string non-empty". Reason: vps_runner accepts hostnames too (Ansible `ansible_host` supports both); strict IP regex would reject valid input. CLI is meta-tool; trust operator input. If onboard fails, error is clear.

### 3.4 Makefile target shape
Mirror the project's existing convention (e.g., `make hub-deploy HUB_NODE=foo`):
```makefile
vps-add-host:
	@test -n "$(ALIAS)" -a -n "$(IP)" || { echo "Usage: make vps-add-host ALIAS=<alias> IP=<ip> [PORT=1156] [USER=ansible]"; exit 2; }
	.venv/bin/python -m plugins.vps_runner.cli add-host $(ALIAS) --ip $(IP) \
	  --env $(or $(ENV),dev) \
	  $(if $(PORT),--port $(PORT)) \
	  $(if $(USER),--user $(USER))
```

Targets respect `ENV` default `dev`; explicit override if needed. `ARGS` slot on `vps-modify` for raw modify flags (`--add-package=htop` etc).
