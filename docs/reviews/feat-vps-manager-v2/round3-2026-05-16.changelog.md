## 2. Intent per change

### 2.1 onboard.yml migration (T2.3 completed in R3)
Round 2 deferred this task because the 545-line vps_manager onboard.yml was too risky to rewrite under T2.3's 1.5h budget. R3 produced a 613-line onboard.yml that:
- reads connection params and per-feature flags directly from host_vars (no `vps_task_*` extravars from a wrapper)
- preserves the **task body verbatim** from the legacy playbook (proven SSH-hardening / managed-user / fail2ban / UFW / unattended-upgrades sequence)
- exposes only the variables ansible itself needs (`ansible_host` / `ansible_port` / `ansible_user`); first-time bootstrap is handled by the CLI passing `extravars={'ansible_user':'root','ansible_port':22}` for that one run, with host_vars staying canonical
- accepts `--ask-pass` / `--ask-become-pass` via runner `cmdline` (plan §3.7 R4 mitigation)

**Deviation from plan §4 T2.3 + R2 — vps_task shim retained** (surfaced to user 2026-05-16, accepted as round-3 closing trade-off):
- Plan said: "grep `vps_task` should reach zero before commit."
- Implementation: `vps_task` is kept as a **local vars-block aggregation** inside the play (lines 26–75), reconstructed from host_vars + role variables; downstream lines reference `vps_bootstrap` / `vps_ssh` / `vps_managed` / `vps_profile` / `vps_firewall` / `vps_fail2ban` etc. (also defined in the vars block, sourced from `vps_task.*`).
- **No external coupling**: `vps_task` is not read by any module / extravar / external file — it is a single-file local; renaming it would not affect any caller.
- **Rationale for keeping**: flattening the 500+ line body required for each of ~80 references to vps_task.* to be individually rewritten — high mis-translation risk for nominal stylistic gain.
- **Action**: tracked as Round 4 follow-up — see §6 *Deferrable*.

### 2.2 modify.yml (T2.6)
A new playbook (the legacy vps_manager had none — modify lived in CLI subprocess flow). 4 schema sections (`packages` / `firewall` / `fail2ban` / `network_tuning`), each optional, each guarded by `when: ... | length > 0` so an unspecified section is a no-op. CLI builds the `vps_changes` extravar from `--add-package` / `--add-port` / `--toggle-fail2ban` and passes it through `ansible_runner.run(extravars=...)`.

### 2.3 remove.yml (T2.6)
Default behavior is a **no-op on the remote** — the CLI does the inventory deletion locally (drops the alias from hosts.yml + deletes host_vars/<alias>.yml). When `--cleanup-remote` is set, the playbook strips the Ansispire-managed sshd drop-ins (so the host's sshd reverts to distro defaults) and re-validates sshd with `sshd -t`. UFW rules and the managed user are intentionally **left** — manual cleanup is the safer default for "I am taking this VPS back".

### 2.4 CLI subcommands (T2.5 + T2.6)
- `onboard`: reads `host_vars/<alias>.yml` first; if `--first-time` is passed, overrides `ansible_user` / `ansible_port` via extravars for the one run; on success calls `record_run(..., set_status='active')`.
- `modify`: assembles `vps_changes` from CLI flags, refuses empty change set with EX_USAGE (64), records the run.
- `remove`: requires `--yes` to guard against accidental removal; conditional remote cleanup; on success deletes inventory entry + host_vars file.
- Common shape: each subcommand reports `run_id` / `artifact_dir` / per-host status / one-line error message via `_print_summary()`.

### 2.5 Core library additions (T2.7 support)
- `read_host_vars` / `write_host_vars` / `delete_host_vars` / `host_vars_path` — YAML I/O on inventory state.
- `record_run` — appends `vps_runner.last_run` + `updated_at` (and optional `status`) after a successful run; used by all three Ansible-running subcommands.
- `remove_alias_from_hosts` — surgical YAML edit on `hosts.yml` (preserves field order via `sort_keys=False`).

### 2.6 Tests (T2.7)
22 tests, all green:
- 12 unit tests on pure helpers (run_id, inventory resolution, list_aliases / list_hosts, read/write/delete host_vars, record_run, remove_alias_from_hosts, _collect_host_results, _first_event_msg)
- 9 CLI dispatch tests (list table / json, modify error paths, remove guard, onboard missing alias, modify extravars assembly, onboard --first-time connection override)
- 1 integration test marked `@pytest.mark.integration`: drives `core.run_playbook` end-to-end against RFC 5737 TEST-NET-1 (192.0.2.99) — guaranteed unreachable so SSH always times out; verifies `summary.status` / `summary.hosts[].status` classification + artifact directory presence.

### 2.7 host_vars schema additions
The shim in onboard.yml reads `vps_runner.bootstrap_user` and `vps_runner.managed_port`. R2 host_vars had `bootstrap_port` but not these two — added in R3 with the correct values per host (`bootstrap_user: root` is the inferred default; `managed_port` matches existing `ansible_port`).
