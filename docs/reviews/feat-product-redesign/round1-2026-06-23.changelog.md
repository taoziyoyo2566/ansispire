## Rationale

The user confirmed the product direction and implementation-step diagram, but
the follow-up review found that creating a fresh custom TS/React/API project
would pre-empt the still-open surface decision and bypass the existing
Semaphore execution baseline.

Official Semaphore UI docs were checked and show that Semaphore already covers
the required MVP control-plane foundations: Inventory, Key Store, Repositories,
Task Templates, Tasks/logs, Schedules, API tokens, and teams/RBAC/auth surfaces.

Therefore the immediate execution path remains inside `ansispire`:

```text
Semaphore UI first
  -> vps-fleet static inventory + fleet key
  -> VPS Audit template
  -> VPS Onboard template
  -> real onboard
  -> managed-channel audit
  -> repeat audit reports 0 changed
```
