## Open items (prioritized)

### Group A — Blockers for *real* onboard/audit execution

| ID | Item | Pri | Problem & evidence | Suggested direction |
|---|---|---|---|---|
| **R1** | Key Store → Ansible SSH credential mapping | **P1** | Worker writes `ansible_ssh_private_key_id=<id>` as a **custom inventory var** that standard Ansible does not consume (`cf-worker/src/inventory.js` `formatHostLine`); `onboard.yml` managed-validation shells `ssh -i <file path>` from the exec env. So a registered host has no usable SSH credential for Semaphore-driven runs. | Decide the model: Semaphore-native key attachment on the template/inventory, or an env/wrapper that resolves the key id. Until done, real onboard/audit will not authenticate. |
| **R2** | Provision real onboard/audit Job Templates | **P1** | `SEMAPHORE_ONBOARD_TEMPLATE_ID` / `SEMAPHORE_AUDIT_TEMPLATE_ID` are empty; onboard-bare returns `412`, audit is disabled. | Create the two Job Templates (bound to `playbooks/vps/onboard.yml` / `audit.yml` + the static inventory), capture ids, set as deploy `--var`/secrets. |

### Group B — Data integrity before production migration

| ID | Item | Pri | Problem & evidence | Suggested direction |
|---|---|---|---|---|
| **R3** | Lossless inventory round-trip for **non-`vps_targets` sections** | **P1** | `serializeInventory` writes only `[vps_targets]` + `[vps_targets:vars]`; `parseInventory` ignores every other section (`cf-worker/src/inventory.js`). Any other group/host in a real inventory blob is dropped on the next write. (Host-var loss within `vps_targets` was already fixed.) | Preserve unknown sections verbatim, or patch only the target host lines instead of re-serializing the whole blob. Hard prerequisite for R4. |
| **R4** | Phase 3 production inventory migration (`file` → `static`) | **P2** (after R3) | `targets-managed` (id `2`) and `production` (id `1`) are still `type: file`; the Worker can only operate on `static`. | Migrate the production inventory to DB-backed `static`, then repoint the Worker. Do **not** target file inventories before this (guard returns `412`). |

### Group C — Worker correctness / lifecycle

| ID | Item | Pri | Problem & evidence | Suggested direction |
|---|---|---|---|---|
| **R5** | `DELETE /vps/:alias` orphans the Key Store entry | **P2** | Delete handler only `removeHost`s the inventory line; the associated Semaphore key is never deleted (`cf-worker/src/index.js` delete route). Also: `triggerTask` failure *after* the inventory write leaves a record with no rollback. | On delete, also delete the host's key; decide rollback/marking for post-write task-trigger failure. |
| **R6** | onboard-bare success → inventory **promotion** + failure live-channel hint | **P2** (after R1/R2) | onboard-bare records `lifecycle_state=onboarding` (bootstrap channel) but nothing promotes it to `managed` after the task succeeds; there is no task-status polling. Failure recovery has no phase markers (see `onboard-execution-models §4/§5`). | Add task-completion detection (poll/webhook) → rewrite the record to managed state on success; emit phase markers (bootstrap-verified → lockdown → bootstrap-closed → managed-verified) for the failure hint. |

### Group D — Production hardening (NFR)

| ID | Item | Pri | Problem & evidence | Suggested direction |
|---|---|---|---|---|
| **R7** | Auth productionization (replace interim Basic Auth) | **P2** | Basic Auth is a single shared operator gate (`requireBasicAuth`), not per-client authz; fine as interim, not for an open REST surface. | Cloudflare Access for humans (IdP/OIDC) + Access **service tokens** for machine/CLI; optionally verify `Cf-Access-Jwt-Assertion` JWT in-Worker (covers all ingresses incl. preview URLs). |
| **R8** | Observability | **P2** | `wrangler.toml` has no `[observability]` block; no structured logging. | Enable Workers logs/traces + structured logging per Cloudflare Workers best practices. |
| **R9** | Deploy-config robustness | **P3** | `--var SEMAPHORE_URL` is per-deploy; a later `wrangler deploy` without it reverts to the placeholder (`cf-worker-deployment.md §4` gotcha). | Move non-secret prod vars to dashboard env vars or a committed non-placeholder env config so deploys can't silently mis-target. |
| **R10** | Inventory write concurrency | **P3** (multi-client only) | Whole-blob read-modify-write is last-write-wins (`design-2026-05-26.md §3.2`). | ETag / optimistic concurrency once more than one writer is realistic. |
| **R11** | CORS for external REST callers | **P3** (if needed) | No CORS headers; only same-origin browser + server-to-server work today. | Add CORS only if cross-origin browser clients become a requirement. |

### Group E — Test / process

| ID | Item | Pri | Problem & evidence | Suggested direction |
|---|---|---|---|---|
| **R12** | `deployed-smoke` in a post-deploy / CI hook | **P3** | The smoke needs `WORKER_URL` + Basic Auth creds, so it is run manually today. | Wire into a post-deploy step with CI secrets so deployment drift is caught automatically. |
| **R13** | Test coverage follow-ups | **P3** | CRUD success paths, audit-alias, key-cleanup, camelCase are covered (28 tests). Gaps remain for promotion (R6), lossless sections (R3), concurrency (R10). | Add tests alongside each feature as it lands. |

1. **Phase A — unblock execution**: R1 + R2 → first real onboard/audit run end-to-end.
2. **Phase B — production data integrity**: R3 → R4 (migrate prod inventory to `static`).
3. **Phase C — lifecycle correctness**: R5, R6.
4. **Phase D — hardening**: R7, R8; then R9 / R10 / R11 / R12 as need arises.
5. **Throughout**: R13 (tests land with each feature).
