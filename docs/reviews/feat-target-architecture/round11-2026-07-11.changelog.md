## Landed

| Step | File | Change |
|---|---|---|
| P2.1 | `playbooks/vps/onboard.yml` | `authorized_keys` now accepts inline `public_key_content` (Semaphore-container contract, no host file), preferred over the `public_key` file-path branch (local-exec compat). Explicit Jinja `if/else` — **not** `content \| default(lookup(...))`, which would eagerly evaluate the file lookup even when inline content is present. |
| P2.2 | `controller/semaphore/docker-compose.yml` | Add read-only mount `./secrets:/etc/ansispire/keys:ro` for the fleet private key(s) used by onboard's `ssh -i` managed-channel validation. **Directory** mount (not a single-file mount) so a missing key file cannot make Docker auto-create a directory in its place. |
| P2.2 | `controller/semaphore/secrets/{.gitignore,README.md}` (new) | Gitignored secret dir (dir tracked, key material never committed) + secret-lifecycle note: why the key exists in both Key Store and a mounted file, who accesses each, rotation, and the future change that removes the duplication. |
| P2.2 | `.gitignore` | Exclude `controller/semaphore/secrets/*` except its `.gitignore` + `README.md`. |
| P2.3 | `playbooks/vps/examples/onboard.{minimal,standard}.yml` | Use `public_key_content` (placeholder pubkey) and set `ansible_key.private_key` to the container path `/etc/ansispire/keys/vps-fleet-key`. |
| P2.4 | `controller/semaphore/bootstrap.yml` | Add `vps-onboard-env` (onboard reference payload from `examples/onboard.minimal.yml` + the same `ANSIBLE_CONFIG` env reused from `vps_audit_env_vars`) and the **`VPS Onboard`** template (onboard.yml + local-workspace repo + `vps-fleet`), both via create + unconditional converge PUT (bound `environment_id`). Extended the post-condition assert to cover Phase 1 **and** Phase 2 resources. |

**P2.2 secret-handling re-check**: the only task rendering key *content* (`Install managed user authorized keys`) already carries `no_log: true`. The `ssh -i <path>` validation tasks pass a filesystem *path* (`/etc/ansispire/keys/...`), not key material — `no_log` not required.

**Deviation (consistent with Phase 1)**: the plan said "extend `bootstrap_preflight.yml`" to assert the onboard resources; the assertion was placed in the **bootstrap post-condition** instead (preflight runs *before* any resource exists and only gates upstream API-shape drift), matching the documented Phase 1 P1.2 decision.
