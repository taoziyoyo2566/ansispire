## Phase 2 Design Highlights

Full design in [`phase2-worker-design.md`](./phase2-worker-design.md). Key points:

- **5 routes**: `GET/POST /vps`, `PUT/DELETE /vps/:alias`, `POST /vps/:alias/audit`
- **Semaphore client**: 4 operations — `getInventory`, `updateInventory`, `createKey`, `triggerTask`
- **Inventory algorithm**: read-modify-write `[vps_targets]` INI blob; last-write-wins (single-tenant acceptable)
- **Extra_vars stub (§6)**: onboard task launch cannot be fully designed until Phase 1 probe confirms the task runtime parameter mechanism. modify / remove / audit use `triggerTask(template_id)` with no overrides — confirmed-working from `controller/audit/reactor.py`.
- **SSH key flow**: browser → Worker memory → Key Store API → key_id in inventory blob (key material never persisted)
- **DB note**: Worker does not connect to the DB; Q2's SQLite/Postgres choice has no effect on the Worker layer.
