## Why this round

Round 11 gave onboard's managed-login validation a **mounted private-key file**
(`./secrets:/etc/ansispire/keys:ro`) because the check shelled out to `ssh -i <path>`
from the controller. Driving it on real hosts exposed two problems the static gate
could not:

1. **uid mismatch** — the Semaphore container runs tasks as uid 1001; a host key
   placed at uid 1000 / mode 600 is unreadable → the `ssh -i` check would fail
   *after* the SSH cutover (same shape as the Phase 1 vault-file abort — but **not**
   vault; a plain file-permission mismatch on the mounted SSH key).
2. **Duplication the operator rejected** — the key already lives in the Semaphore
   Key Store (it drives the transport); a second on-disk copy is redundant and
   operationally fragile.

Probing the running Semaphore confirmed it materializes the Key Store key as a
**transient temp file** (no ssh-agent; `SSH_AUTH_SOCK` unset), so a stable path
for a manual `ssh -i` genuinely isn't available — which is exactly why the mount
existed. The right fix removes the manual `ssh -i` instead.

## Landed — redesign (supersedes round 11's mount)

| File | Change |
|---|---|
| `playbooks/vps/onboard.yml` | Managed-channel validation now runs over **ansible's own connection**, re-pointed to `managed_user @ managed_port` via **task-level connection vars** (`ansible_user`/`ansible_port` + BatchMode common args). It reuses the exact private key the run was invoked with (Semaphore Key Store `--private-key`, or a local `--private-key`) — **no mounted key file, no uid juggling**. Task-scoped vars keep the bootstrap connection (root@bootstrap) intact through cutover. Dropped the `ansible_key.private_key` requirement/assertion (replaced by an `authorized_keys` non-empty assert). |
| `playbooks/vps/onboard.yml` | **fail2ban-on-RHEL fix**: install `epel-release` before `fail2ban` on RedHat family (fail2ban is not in the RHEL base repos). |

- **Phase 3 gate met for u24 + d13**: onboard → managed user/key/sudo + SSH cutover
