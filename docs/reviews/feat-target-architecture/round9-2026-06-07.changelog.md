## Scope

Close the Worker live-integration gap left by Round 8:

1. Add a repeatable live integration harness for the Worker.
2. Fix the runtime issue found only under Cloudflare Workers remote preview.
3. Validate deployed Worker routes against the live Semaphore probe `static` inventory.
4. Keep production `targets-managed` inventory untouched.

## Behavior Confirmed

- Deployed Cloudflare Worker can reach `https://semaphore.saberu.com` through Cloudflare Tunnel.
- Worker reads and mutates Semaphore probe `static` inventory id `3`.
- Worker route behavior is valid in the Cloudflare runtime, not only in Node/local tests.
- `SEMAPHORE_INVENTORY_ID=3` was used for all live/deploy validation; production-facing `targets-managed` inventory id `2` was not mutated.
- After the security review, the Worker now requires Basic Auth for the browser
  wizard and `/vps` routes. `/health` remains public for uptime checks.
- After the mode review, the Wizard/API no longer treat all adds as generic
  inventory-only writes. Register-managed records the managed channel; onboard
  of a bare `root@22` host is explicit and requires an onboard template.
- After the inventory-type review, the Worker refuses to list or mutate
  Semaphore `file` inventories. This prevents production `targets-managed`
  inventory id `2` from being parsed as an empty static blob and overwritten.
