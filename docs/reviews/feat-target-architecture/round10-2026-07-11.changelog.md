## Root Cause — Why the first live audit failed (and the fix)

The operator completed P1.5/P1.6 and ran `VPS Audit`; tasks #1 and #2 **errored** at config-load:

```
[ERROR]: Could not read vault password file '/workspace/.vault_pass': [Errno 13] Permission denied
```

`0b68119` had added a vault-free `controller/semaphore/ansible.cfg` and wired it via `ANSIBLE_CONFIG` in the container's docker-compose env — but the **Semaphore task runner does not inherit the container process env**. So the template run's `ansible-playbook` (cwd `/workspace`) auto-loaded the repo-root `ansible.cfg`, whose global `vault_password_file = .vault_pass` aborts on the host-only secret (uid mismatch — GOTCHA 1). Two defects compounded this:

- **A**: `vps-audit-env` carried only `json` (the `vps_task` vars), no `env`. The Semaphore-native way to inject a process env var into a task is the bound Environment's `env` field.
- **B**: the `VPS Audit` template had `environment_id=0` — it was never bound to `vps-audit-env`, so even a corrected env would not reach the runner.

Both fixed in `bootstrap.yml` (Fix A / Fix B above) as **create-body + unconditional converge PUT** so fresh installs and existing (mis-created) installs both reach the desired state.
